# Wechat-Agent 新架构总览（v4，2026-08-08 重写）

> 本文是架构唯一总纲。三层详细职责见同目录三个分文档。
> 旧实现位于 `/media/data_old/wechat-agent-old/`（下称 old 仓库），仅作资产继承参考。

## 一、设计目标

1. **三端可用**：同一套核心逻辑，微信客户端在 Android / Windows / macOS 上都能操控。
   平台差异全部收敛到交互层的"端口"实现里，上层无感知。
2. **双 agent 结构**：一个"模拟成用户的 bot"（人格化、泡在微信里聊天），
   一个"能力非凡的核心"（自由调用工具、子代理，完成复杂任务）。
   两者之间有明确的对话/移交通道。
3. **确定性的事交给剧本，需要智能的事交给模型**：
   感知、发现、防风控节奏是确定性代码；决策、任务规划、异常脱困是模型。
4. **模型无关**：LLM 走 provider 抽象（k3 / DeepSeek / 本地模型可热替换）。

## 二、三层划分

```
┌─────────────────────────────────────────────────────────────┐
│ 决策层（决策/规划/任务执行核心）                                │
│  对话决策 · 任务模式(长任务/子代理) · provider 抽象 · 升级仲裁   │
└──────────────▲───────────────────────────┬──────────────────┘
               │ 事件/上下文/任务结果         │ 工具调用(schema)
               │                            ▼
┌──────────────┴──────────────────────────────────────────────┐
│ 交互层（微信的一切进出 + 人格伪装）                              │
│  平台端口(observe/act) · 消息发现/读取 · 消息日志 · 人格 · 防风控  │
└──────────────▲──────────────────────────────────────────────┘
               │ UI 原语 / 系统能力
               ▼
┌─────────────────────────────────────────────────────────────┐
│ 工具层（被调用的能力集合）                                       │
│  计算机工具 · 网络工具 · 视觉工具 · 微信动作工具 · UI 原语         │
└─────────────────────────────────────────────────────────────┘
```

- **交互层**：微信的进出通道 + "像人"的全部学问。对上只暴露语义化事件与动作。
- **决策层**：唯一调用 LLM 的层。决定"回不回、回什么、做什么任务"。
- **工具层**：纯能力，无状态、无决策，被决策层按标准 schema 调用。

详细职责：[交互层](./INTERACTION_LAYER.md) · [决策层](./DECISION_LAYER.md) · [工具层](./TOOL_LAYER.md)

## 三、层间接口（契约先行）

| 接口 | 方向 | 内容 |
|---|---|---|
| `MessageEvent` | 交互层 → 决策层 | 新消息/红点/@我 事件（会话、发送人、内容、多媒体标注、mention 标记） |
| `SessionContext` | 交互层 → 决策层 | 会话历史（msg_log 读取，[@我]/多媒体已标注） |
| `ActionRequest` | 决策层 → 交互层 | 发送文本/图片/引用等语义化动作，不指定坐标 |
| `TaskBrief` / `TaskResult` | 交互层 ⇄ 决策层（任务模式） | 升级移交的任务简报与结果回传 |
| `ToolSchema` | 工具层 → 决策层 | 标准工具声明（name/description/JSON Schema/限流） |

关键规则：**坐标、像素、平台细节不许越过交互层上界**；LLM 不许出现在交互层和工具层。

## 四、升级通道（剧本 → 核心）

交互层的确定性剧本（发图流程、引用回复、面板操作）是第一选择——便宜、快、可靠。
剧本失败或遇到未覆盖场景时，不报错退出，而是生成 `TaskBrief`（要做什么、试过什么、
卡在哪、当前屏幕状态）移交决策层任务模式：由核心用 UI 原语自由试错，完成后交还。

## 五、从 old 仓库继承的资产

以下已在 old 仓库真机验证，重写时逐块迁移/封装，**不重写逻辑**：

- `src/v2/` 感知层（13 parser、头像顶切段、区域标定、红点/未读/@前缀识别，268+ 测试）
- `src/device_ctl.py` / `random_touch.py` / `layout.py`（ADB 操控、随机化、两态布局常量）
- `src/msg_log.py` / `frame_align.py`（消息日志、幂等续写、回填拼接）
- 发图/引用/加号面板的真机验证流程（docs/SEND_IMAGE_OCR_FLOW.md 等）
- 通知监听（dumpsys）、网关/可视化、人格卡（config/personas/*.yaml）

## 六、不做的事

- 不追求多设备自适应框架——端口内部仍允许硬编码标定，每端一份
- 不上重编排框架——决策层先用轻量循环 + provider 抽象，复杂度只在需要时引入
- 微信协议接入（封号风险）永不考虑，非侵入式是唯一路线
