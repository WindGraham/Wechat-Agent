## 1. 总体目标与核心思路

**目标**：进入微信群聊后，自动/半自动采集【上次会话之后的新消息】，逐条识别（发送者、内容、时间），并**可视化验证整个采集-拼接-识别链路是否正确**。

**核心思路**（一句话）：
- 从最新屏向**更早**逐屏滚动；
- 相邻两屏按**实测位移 dy** 缝合（union / A-B 差分缝合），保证每条消息在某次 union 中被**完整包含一次**；
- 用**统一裁切线**（头像上边缘 + 时间戳边沿）切分消息段；
- 每段做**双因子匹配**（头像图像 + 昵称 OCR），输出识别方式与匹配度；
- 滚动到**上次书签**（上次会话第一屏）被 union 完整包含 → 新消息采完 → 停；
- 全程落盘 replay，网关页面可视化验证。

## 2. 几何前提

```
消息区高 M ≈ 1890px（屏 [200, 输入栏顶 2119]）
每次滑动 dy 必须满足：0 < dy < M
```

- `dy < M` → 相邻两屏**必有重叠** → 书签（1 屏高）从「完全在上一屏」到「完全在下一屏」**必然经历跨两屏时刻**，那一刻两屏 union 完整包含书签（匹配 conf≈1.0），不会漏检。
- 完整消息判定：`一条消息完整 ⟺ [本条头像顶, 下一条消息的头像顶] 两条边界都在识别区域内`。

| 残缺类型 | 表现 | 可恢复性 |
|---|---|---|
| 顶部残缺 | 有文字泡，头像不是完整正方形、昵称不全 | ✅ 可恢复：滚更早，头像露全 |
| 底部残缺 | 正文尾被输入栏切掉 | ❌ 不可恢复：尾巴在更新侧 |

向更早翻时，**需要缝合补全的只有顶部残缺**；底部残缺的完整版在更早的 union 已采过，靠去重跳过。

## 3. 书签机制（新消息截止点）

**书签 = 上次会话看到的最新位置 = 新消息的截止线**。

```
                更旧（历史，已采过，不重复入库）
                ↑
    ┌─────────────────────┐
    │   更旧内容（历史）    │
    │        ↑            │
    │   ──书签 N0──        │  ← 截止线：上次会话的最新屏（内容区裁图）
    │        ↓            │
    │   新消息（本次要采）  │  ← 书签下方 = 本次新增，全部入库
    │        ↓            │
    │   本次首屏 N1（最新） │  ← 本次进入时的最新屏，结束时存为【下次】书签
    └─────────────────────┘
                ↓
                更新（最新消息）
```

**新消息集 = [书签 N0 上边界, 本次首屏 N1 下边界]**。

- **存书签**（`_save_anchor`，每次采集结束时）：本次第一屏（最新）→ 裁内容区 → 存 `workspace/runtime/collect_anchor_<group哈希16>.jpg` + 展示副本 `workspace/bookmarks/<群>/full.jpg|crop.jpg|meta.json`。
- **读书签**（`_load_anchor`）：按群名哈希找文件，旧格式（>2200px 整屏）自动裁内容区兼容。
- **识别书签**（`_anchor_in_union`）：`matchTemplate(union, 书签)` TM_CCOEFF_NORMED 全图检索，conf ≥ 0.8（`ANCHOR_COVER_SUM`）判定「union 完整包含书签」→ 新消息采完 → 停。

**真实数据验证**：`replays/20260814_141108` 106 屏，滚动到第 105 屏 union 完整包含书签 conf=0.97 自动停止。

## 4. 采集流程

```
前置：进入群聊，停在最新底部（微信进入会话即最新位置）
循环（每轮）：
  1. 滑动向更早（见 §11 滑动经验）
  2. 等待滚动完全停稳（连续 4 帧像素差 < 2.0 且保持 1.5s）
  3. 截图
  4. dy 检测（见 §5）；滑动异常（dy<100 或负）→ 重滑重截
  5. 拼接 union / A-B 缝合段（见 §6）
  6. 统一裁切线分段（见 §8）
  7. 每段识别 + 匹配度（见 §9）
  8. 落盘 full/crop/stitch + manifest（含 msgs/avatar_lines）
  9. 书签检测：union 完整包含书签 → 停
结束：存本次第一屏为下次书签
```

落盘结构：
```
workspace/replays/<时间戳>/
  screen_NN_full.jpg   原图
  screen_NN_crop.jpg   消息区裁切 [367, 2119]
  screen_NN_stitch.jpg 缝合段（A2 上 + B1 下）
  manifest.json        dy / crop_top / crop_bottom / split_y / stitch_h
                       / msgs（段列表）/ avatar_lines（头像上边缘）
```

## 5. 重叠检测（dy）

### 5.1 智能 dy（`scroll_stitch._dy_multi_band`）

多带共识 + 像素差验证 + 物理范围约束：

1. **多带采样**：n_bands=6 个不同 y0 横带（`band_h = H//n_bands` 自适应），纹理过滤（`_band_texture < 0.08` 跳过纯背景带）；
2. **物理范围**：`dy ∈ [100, H-30]`（小步长 dy≈300-340，fling dy≈1250-1700，小于 100 = 未滚动）；
3. **像素差验证**（`_pixdiff_at`）：`absdiff(cur[0:H-dy], prev[dy:H]).mean()`，只用于剔除假匹配（conf 高但像素差极大）；
4. **conf 最高优先**：内容真实变化时像素差失去区分度，取模板 conf 最高的带（实测顶部带 conf 0.999 才是真位移）；
5. **多带共识加分**：≥2 带指向同一 dy（|Δ|<20）→ conf 提升到 ≥0.85；
6. conf = `1/(1+像素差/20)`。

### 5.2 兜底（`_find_overlap_dy_fullscreen`）

裁切版测不出时回退全屏测量；H<2000 的裁切图跳过输入栏检测（避免越界崩溃）。

## 6. 拼接（union / A-B 缝合）

### 6.1 union（书签检测用）

```
union = vstack([
    cur[内容顶 : 内容顶 + dy],   # cur 顶部新增段（更旧）
    prev[内容顶 : 输入栏顶]       # prev 完整内容区（更新）
])
```
不重行不丢行，正好 1.75 屏高，能完整容纳 1 屏书签。

### 6.2 A-B 缝合段（消息识别用）

```
第 1 屏：找第一个完整头像 → 上边缘切 A1（完整段）和 B1（残缺段）
第 N 屏：A2 = 本屏[split : dy]（新增完整段），B1 = 上一张[0:split]（顶部残缺）
缝合 = vstack([A2, B1])   # A2 上（更旧）+ B1 下（更新）
```

**缝合顺序为什么对**：聊天内容旧在上、新在下。跨边界消息 M：A2 里有 M 的头（头像+开头），B1 里有 M 的尾（正文尾），拼起来 M 完整。

**接缝黑线修复**：内容区裁切起点跳过黑带过渡行（366→367，见 §7），避免 B1 顶部第一行是暗线导致接缝出现黑缝隙。

## 7. 固定 UI 排除（置顶条 / 输入栏）

### 7.1 置顶条底（`detect_pinned_bar_end`）

深色背景：找最后一个**纯黑带**（行内 std<3.0、mean<25、连续≥3 行——std 放宽到 3.0 容忍压缩噪声），返回**黑带结束+1**（跳过过渡行 366→367，第一个内容行）。浅色背景回退气泡掩膜方案。

### 7.2 输入栏顶（`detect_input_bar_top`）

方案 B（深色背景）：从上往下第一条「本行 mean<50 且连续 15 行 std<4，且**从该行直到底部暗像素占比>80%**（尾暗约束，排除消息内容里的深色块）」→ 2119。

**实测**：56 屏全部稳定 367/2119，旧背景回归通过。

## 8. 统一裁切线分段

**裁切标准（用户定稿，非常单一）**：
- **① 头像上边缘**（`avatar_top_lines`）：完整头像顶，贴裁切顶的残缺头像跳过；rescue 通道尺寸达标（h 100~150、宽高比 0.8~1.25）也接受（screen_01 实测 rescue 头像全被旧判据排除 → 蓝虚线 0 条）。
- **② 时间戳上下边沿**（`timestamp_edges`）：水平中间段（x 250-830）连通圆角矩形，OCR 时间格式定位（`\d+:\d+`）+ 非背景像素扩展。

相邻裁切线之间 = 一段消息。段输出：`y_top / y_bottom / content / factor / avatar_score / nick_score / avatar_cand / nickname`。

**与 slice_chat 区别**：不依赖气泡完整性 → 缝合 union 接缝处被切开的跨接缝消息天然正确处理。

## 9. 识别与匹配度

### 9.1 双因子匹配（`roster_matcher.match_dual_factor`）

返回 `(matched, name, info)`，info 含：
- `avatar_score`：`_match_image_score` 复合分（归一化 BGR 模板 + Hue 直方图，抗偏色）；16×16 缩略图签名预筛 top-50 候选再全量匹配；
- `avatar_cand`：该分对应候选成员昵称；
- `nick_score`：OCR 昵称 vs 候选主/群/曾用群昵称的匹配分（`_nick_similarity`：完全相等/包含→1.0，否则 LCS 归一化 `2*LCS/(len_a+len_b)`）；
- `thresh`：头像阈值（0.70）。

**判定**：`avatar_score ≥ 0.70 且 nick_score ≥ 0.60` → 双因子；无昵称 OCR 时 `nick_score = 1.0 if avatar_score ≥ 0.85`（头像高分代偿）。

### 9.2 识别方式标签

| 标签 | 含义 |
|---|---|
| 🟢 双因子 | 头像图像 + 昵称 OCR 双命中（花名册） |
| 🟡 单因子 | 仅头像或仅昵称命中（含多媒体消息） |
| 🔴 未知 | 昵称 OCR 失败且头像双因子失败 |
| ⚪ 时间 | time_divider 时间戳 |
| 🔵 自己 | 我发的消息 |

## 10. 可视化页面

网关 Flask :13014，页面动态读 manifest。

### 10.1 滚动回放 `/scroll_replay?r=<replay>`

每屏一行 4 列：
| 原图 | 消息区·与上一张重叠 | 消息区·与下一张重叠 | 分割残缺块 |
|---|---|---|---|
| 全屏截图 | 蓝遮罩=本屏底部重叠 `[dy:高]` | 红遮罩=本屏顶部重叠 `[0:高-dy]` | 黄虚线=首头像顶 |

### 10.2 滚动连续流 `/scroll_flow?r=<replay>`（5 列，核心）

| 列 | 内容 | 展示 |
|---|---|---|
| 1-2 | 蛇形原图（左偶/右奇，从底向上，红蓝贯穿线） | 相邻屏重叠同高对齐 |
| 3 | 缝合结果（A2 上 + B1 下，黄虚线裁切线） | 跨边界消息完整性 |
| 4 | 同一 stitch + **蓝色细虚线 = 头像上边缘**（每条消息 1 条线，横跨 4+5 列） | 消息级切分 |
| 5 | 每段卡片：**内容 + 识别方式 + 匹配度（头像%/昵称%→候选）** | 识别质量 |

**布局要点**：dy<0 的屏（滑动异常）按 dy=0 处理不产生位移，避免重叠遮挡。

### 10.3 书签页 `/bookmark`

书签 full + crop + 绿框裁切范围。

## 11. 真机滑动经验（踩坑记录）

| 坑 | 现象 | 结论 |
|---|---|---|
| 滑动方向 | 采集 dy 负/0 | **手指向下（y 小→大）= 看更早**（页面内容上滚，新消息从底部进是手指向上=看更新） |
| 慢速拖动不滚动 | `input swipe ... 700ms` dy≈0 | 微信慢速拖动（≥700ms）被识别为拖动结束，**必须快速 swipe（fling，<300ms）触发惯性** |
| fling 位移不稳定 | dy 1148/4/349/-982 波动 | 微信 fling 惯性随机（吸附/回弹），**不能预设步长，必须每屏实测 dy** |
| 最新底部慢拖 | dy 负 | 慢拖在底部触发回弹；fling 从底部可靠离开 |
| 会话列表点错群 | 采到别的群 | 用**搜索**进群最可靠；采集后**校验标题一致性** |
| 群活跃 | 重叠带像素差高 | **不影响 dy 检测**（新消息插入不改变已有消息位置）；dy 波动来自滑动物理 |

**当前建议采集方式**：
- 首屏（最新底部）：fling（快速）离开底部
- 后续：快速 swipe 向更早，每屏实测 dy，不预设步长
- 滑动后等完全停稳（多帧稳定 + 保持 1.5s）再截图

## 13. 已知问题与待办

1. **dy 检测在 fling 大位移 + 重叠小时不可靠**（conf 低时返回值不可信）——低 conf 应重试而非采信；
2. **滑动位移不可控**（微信 fling 惯性随机）——考虑 getevent 实时监控真实滚动量，或接受实测 dy；
3. **无法感知用户手动操作**——`adb getevent` 可实时读取触摸事件流（`/dev/input/event*`），解析坐标/位移，配合用户手动滑动协作；
4. **活跃群滚动时重叠带消息"换批"**（新消息插入重叠区）——生产靠 union+去重兜底，可视化 replay 重叠带像素差作为诊断信息；
5. **矮 stitch 屏**（滑动异常 dy 负导致 stitch<500px）——segment_cutlines 跳过，可视化标注异常；
6. 可视化增强方向：实时采集直播 HUD、交互式点图看详情、差分热力图、书签进度条、新旧算法并排对比。
