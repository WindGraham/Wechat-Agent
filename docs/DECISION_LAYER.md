# 决策层（Decision Layer）

> 本项目的 agent 核心。**如何回复用户信息，决策权全部在这一层。**
> 系统里唯一调用 LLM 的层。

## 一、核心职责

### 1. 回复决策

对交互层上报的 `MessageEvent` 逐会话决策：

- 私聊必回；群聊 @我 必回（逐条）；主人说话必回
- 群聊普通消息：结合上下文自由决策，沉默（[SILENT]）是合法输出
- 输出直接是"要发给用户的内容"，经交互层 `ActionRequest` 落地

### 2. 人格

- 人格卡（身份/性格/说话风格/规则/核心记忆）在这里加载和注入 prompt
- 按会话覆盖（底座卡 + 会话卡）
- 决策层输出的是"人格化后的最终话术"，交互层不加工

### 3. 记忆

- 短期：会话滑动窗口（经 `SessionContext` 读取）
- 长期：经工具层检索历史消息
- 上下文组装：人格 + 聊天记录 + 当前触发消息 + 屏幕状态摘要

### 4. 任务分发（与工具层的对话）

当用户需求超出"回一句话"的范畴（找图发图、查资料、整理文件、多步操作），
决策层把任务写成简报交给工具层执行：

```python
TaskBrief(
    goal: str,               # 要达成什么
    context: str,            # 相关聊天上下文
    tried: list[str],        # 已经试过什么、失败现象
    deliver: str,            # 结果交付方式（发到哪个会话/存到哪）
) -> TaskResult(ok, summary, artifacts, say_to_user)
```

- 决策层负责判断"这件事我自己答还是交工具层做"
- 拿到 `TaskResult` 后把 `say_to_user` 人格化回复出去
- 工具层执行期间，决策层可以继续处理其他会话（异步任务，按 task_id 回调）

### 5. Provider 抽象

- LLM 调用走统一接口，模型可热替换（k3 / DeepSeek / 本地端点）
- 工具调用协议目标为原生 function calling

## 二、运行循环

```
等待交互层事件
  → 闸门（全局暂停/静默、群类型规则）
  → 组装上下文（人格 + 记忆 + 屏幕状态）
  → LLM 决策：
      ├─ [SILENT]                → 结束
      ├─ 回复文本                 → ActionRequest(text)
      ├─ 需要工具/任务            → TaskBrief → 工具层 → 结果 → 人格化回复
      └─ @我/必回场景沉默时       → 强制重试一次，仍沉默用兜底话术
```

## 三、明确不做

- 不感知平台（不知道消息来自安卓还是桌面端）
- 不碰坐标/像素/控件
- 不自己实现工具框架（那是工具层——现成 CLI 的事）
