# 采集识别设计定稿：重叠-残缺-缝合 + 书签续采

> 2026-08-14 定稿。本文件是「增量采新消息 + 完整消息识别」的**唯一设计依据**，
> 实现必须严格按本文件，不再另起炉灶。
>
> 解决的问题：进会话 → 采到上次会话之后的新消息 → 拼接 prompt；
> 并且识别过程中**长消息/跨屏消息不漏、不重、不残缺**。

---

## 〇、核心结论（一句话）

进会话第一屏就是最新屏，从它开始**向更早翻**，每两屏按位移拼成 union 识别，
用「[本条头像顶, 下条头像顶]」判完整，滚到**上次书签屏（union 完整包含它）**即
停——这批就是从上次会话之后的新消息。

---

## 一、几何前提（必须先满足）

| 量 | 值 | 说明 |
|---|---|---|
| 消息区高 M | ≈1890px | 内容区 `[内容区顶200, 输入栏顶~2090]`，不含状态栏/标题栏/输入栏 |
| 每次滑动 dy | **0.75 × M ≈ 1417px** | 消息区的 75%，**不是全屏的 75%** |
| 相邻两屏重叠 | 0.25 × M ≈ 473px | 因为 0.75 < 1，**必有重叠** |
| 两屏 union 高 | dy + M ≈ 3307px ≈ 1.75 屏 | 能完整装下一屏书签（1 × M） |

**滑动距离有上下限，且必须满足：`0 < min ≤ dy ≤ max < M`。**
这是整套方案的成立前提：
- `dy < M` → 相邻两屏必有重叠 → 书签（1 屏高）**必然被某次两屏 union 完整包含**，不会漏检；
- `dy > 0` → 每次真实推进 → 命中窗口 ≥ min 是一段区间，抗抖动。

---

## 二、书签（视觉断点）

- **定义**：书签 = 上次会话**进入时看到的最新屏 N0**（标记「新消息从哪里开始」）。
- **保存**：进会话第一屏（最新屏 N1）存为下次书签；存**内容区** `[200, 输入栏顶]`，
  不含标题栏/输入栏（固定 UI 无重叠信号、还会在输入栏状态变化时污染匹配）。
- **检测**：当前屏滚动过程中，**两屏 union 完整包含书签**即判定「滚到上次位置」——
  因为 `dy < M`，书签从「完全在上一屏」到「完全在下一屏」必然经历跨两屏时刻，
  那一刻 union 完整包含书签 → `matchTemplate(union, 书签)` conf ≈ 1.0。

---

## 三、识别顺序（从最新向更早，单方向）

```
A：从最新 N1 向上翻到 N0（采用）        B：先找 N0 再向下翻回 N1（废弃）
```

- 进会话第一屏即最新 N1，天然起点；
- N0 是**更早**的位置，向更早翻**顺路**就把新消息 `[N1, N0]` 全识别了，到 N0 即停；
- 反方向要「先滚到 N0 再滚回来」，白滚一个来回，废弃。

---

## 四、完整消息判定（关键）

```
一条消息完整 ⟺ [本条头像顶, 下一条消息的头像顶] 两条边界都在识别区域内
```

| 残缺类型 | 表现 | 可恢复性 |
|---|---|---|
| **顶部残缺** | 有文字泡，但头像不是完整正方形、昵称显示不全（头像顶在区域上方） | ✅ 可恢复：滚更早，头像露全 → 完整 |
| **底部残缺** | 正文/引用尾被输入栏切掉（下条头像顶在区域下方），如「带引用的消息被输入栏截断」 | ❌ 不可恢复：尾巴在新的一侧，滚更早看不到 |

向更早翻时，**需要缝合补全的只有顶部残缺**；底部残缺的完整版在更早的 union 里
已经采过，这里靠去重跳过。

---

## 五、重叠-残缺-缝合算法（核心，A/B 差分缝合）

滚动方向：**从下往上滑（看更早）**。处理对象**不是截出来的整屏**，而是差分缝合段。

```
第 1 屏 S1：
  1. 找到自上而下第一个【完整头像】（头像顶 + 昵称完整）
  2. 从该头像【上边缘】切割：
       上边缘之下 = A1（含完整头像及以下 = 完整消息段）
       上边缘之上 = B1（无完整头像，必是残缺：头像/昵称不全的顶部残缺）
  3. 识别 A1：每条消息 [头像顶, 下条头像顶] 都在 A1 内 → 全部完整 → 入库

向上滑 → 第 2 屏 S2：
  1. 先和 S1 做重叠识别（find_overlap_dy 得 dy）
  2. 把【重叠部分完全裁切掉】→ 只剩新增部分
  3. 对新增部分同样找第一个完整头像 → 上边缘切出 A2（完整段）和 B2（残缺段）

缝合：
  B1 + A2 拼在一起 → A2 在上、B1 在下
  → 拼接出的这一段里，每条消息都完整 → 识别入库
```

**缝合顺序 A2(上) + B1(下) 为什么对**：聊天内容旧在上、新在下。
A2 来自 S2（更早屏）的完整段 = 更旧 → 在上；B1 来自 S1（更新屏）顶部残缺 = 更新 → 在下。
跨边界消息 M：A2 里有 M 的头（头像+开头），B1 里有 M 的尾（正文尾），拼起来 M 完整。

## 六、完整采集流程

```
① 进会话 → 捕获第一屏 N1（最新屏）→ 存为【下次】书签
② 循环（向更早翻）：
   cur = 捕获当前屏
   dy, conf = find_overlap_dy(prev, cur)      # 实测位移
   conf<0.5 → 糊帧重截；dy<40 → 等 3s 懒加载再滑一次确认；仍不动 = 到底，停
   # A/B 差分缝合（见第五节）：
   union = 缝合段（A2 上 + B1 下，或首屏 A1）
   识别 union：
       顶部残缺（头像顶在 union 上界外）→ 跳过，下一 union 补全
       [头像顶, 下条头像顶] 都在 → complete → 入库（fuzzy 去重）
       底部残缺（下条头像顶在 union 下界外）→ 完整版已采过，跳过
   # 书签检测：
   if union 完整包含上次书签 N0 → 新消息采完 → 停
   prev = cur；滑动 older（dy≈1417px）；sleep
③ 结束：_save_anchor(group, N1)   # 存本次最新屏作下次书签
```

## 七、回复场景 → 采集场景（引用场景）

```
① 进会话 → 截第一屏 = 本次最新屏 N1（存为下次书签）
② 若需引用：先滑动到书签 N0 甚至更早 → 找到被引用的消息
   （引用块里带着那条消息的原文）→ 引用回复 → 发出
③ 发出后：画面自动跳回最新 N1（微信行为，天然便利）
④ 退出前：从最新 N1 开始，向更早翻 + A/B 缝合，识别到 N0 为止 = 新消息采集
```

**便利点**：发完消息画面自动跳回最新，步骤③④不需要重新滚回最新，天然从最新开始采集。

## 八、识别准确性保障

| 问题 | 手段 |
|---|---|
| 长消息（>473px）漏采 | union 识别（1.75 屏）：≤1 屏高的消息必然被某 union 完整包含 |
| 跨屏残缺消息 | A/B 差分缝合：顶部残缺的头部/尾部跨屏接上 |
| 重复入库 | fuzzy 去重（精确 + ≥0.85 模糊），重叠 25% 跨 union 只入一次 |
| 多媒体 | OCR 提取段内文字 + media_archive 裁图归档 + 占位符 |
| 时间线 | time_divider 独立入库，作 ts_hint |
| OCR 漏字 | bubble_model 几何补读 + fill_missing_lines |
| 系统消息（入群/撤回） | 暂跳过（可选项，后续可补） |

## 十一、固定 UI 排除（置顶栏 / 输入栏）——逐屏条件检测（2026-08-14 定稿）

不是每个界面都有置顶栏，也不是每个页面的输入栏高度都一样。固定 UI 一律
**逐屏检测、有才排除**，检测不到回退固定值。

### 输入栏顶（`page_detector.detect_input_bar_top`）

用户定稿方案：输入栏顶是一条【贯穿屏幕左右的分界线】。行投影「略亮像素」
(内容区背景 bg+2 ~ bg+40) 占比：输入栏本体（含按钮行）≈86~100%，消息泡/
卡片最高 ≈79%。规则：从上往下找第一条「本行及后续 15 行占比都 ≥85%」的行。
检测不到回退固定 `INPUT_BAR_Y0=2110`（三圆钮检测作兜底）。

### 置顶消息栏（`page_detector.detect_pinned_bar_end`）

复用 `chat_parser.py` 已有的置顶条学习方案：**气泡掩膜连通域**里的顶部全宽
细条（w>900、h<170、x<30、y<600）= 置顶消息条。置顶条文字行被灰色底包围，
闭运算（close_ksize=9）填洞后是一个完整连通域，bbox 精确覆盖整条（行投影
会被文字行凹陷骗到，2026-08-14 实测）。返回条下边界 y+h+1；**无置顶条返回
None**，调用方回退内容顶 `CONTENT_Y0=200`。

离线验证四场景：有置顶栏→345 / 无置顶栏→None / 短置顶条→301 / 纯背景→None。

## 十二、网关可视化页面格式（滚动回放 / 滚动连续流）——2026-08-14 记录

### 页面一：滚动回放 `GET /scroll_replay?r=<replay>`

每屏一行 4 列（`pages/scroll_replay.html`）：
| 原图 | 消息区 · 与上一张重叠 | 消息区 · 与下一张重叠 | 分割残缺块 |
|---|---|---|---|
| 全屏截图 | 蓝遮罩=本屏**底部**重叠 `[dy:高]` | 红遮罩=本屏**顶部**重叠 `[0:高-dy]` | 黄虚线=首头像顶，B 顶部残缺在上 / A 完整段在下 |

方向语义（用户定稿）：滚动 older 内容下移 dy → **新屏顶部 == 旧屏底部**（同一段
内容），重叠标注按此方向（曾标反，2026-08-14 修正并像素验证对齐差 1.8）。

### 页面二：滚动连续流 `GET /scroll_flow?r=<replay>`（三/四列，用户定稿格式）

**三列蛇形布局**（`pages/scroll_flow.html`）：
- **列 1（左）**：session0、2、4…（偶数屏，消息区图）
- **列 2（右）**：session1、3、5…（奇数屏）
- 从**底部向上接**：每张比上一张高 dy（缩放 s = 显示宽/1080），相邻屏重叠内容
  **同一高度**（像素验证：session0 顶部重叠带 [3235.85, 3336.6] == session1 底部重叠带）
- **红/蓝贯穿线**（只横跨前两列，宽 2W+GAP）：蓝线=与上一张重叠（本屏底部边界）、
  红线=与下一张重叠（本屏顶部边界），成对框出共享内容带，便于横向对比
- **黄色裁切线**（每张图内，黄虚线）：`首头像顶 y=xxx`（分割 B 顶部残缺 / A 完整段）

**列 3（单列）**：每屏的**去重+拼接结果**（缝合）——去掉与上一张的重叠（本屏底部），
补上上一张的残缺部分（B1 = 上一张 `[0:split]`），即 A/B 缝合段 **A2（上）+ B1（下）**：
- session0：A1 = `[split_0 : H]`（完整段）
- session i≥1：`A2 = 本屏[split_i : dy_i]` + `B1 = 上一张[0:split_{i-1}]`
- 纵向位置与左两列**同高对齐**（A2 对齐本屏新增部分、B1 对齐上一张顶部残缺）
- 黄色裁切线保留：顶部=本屏首头像裁切处、底部=上一张首头像裁切处
- **无红蓝线、无缝合线**

**列 4（规划中，未定稿）**：缝合结果 + 黄色裁切线保留 + **灰色细虚线**=每条消息间的
分割线。消息边界识别拟用**花名册作参考**（`RosterMatcher` 头像模板在头像列滑窗
匹配，检出几何检测器漏掉的引用消息头像；16×16 签名 L2 距离预筛快匹配）。
⚠ 2026-08-14 实测花名册滑窗跨屏不稳定（部分成员头像不匹配→漏边界；部分屏假阳性
→多边界），尚未定稿；且回放序列中发现 2→3 屏间内容断档（对齐差 10.5，疑似漏截

### 13.1 智能 dy（`scroll_stitch.find_overlap_dy` 重写）

旧版缺陷：固定顶部横带(300px) → 大 dy(>1453) 横带越界假匹配；纯背景横带误配；
只看模板 conf（conf 高但位置错）。

新版 `_dy_multi_band`（全自动，判据均为可测物理量）：
1. **多带采样**：n_bands=6 个不同 y0 横带（`band_h = H//n_bands` 自适应屏高），
   纹理过滤 `_band_texture(band)<0.08` 跳过纯背景带；
2. **物理范围约束**：`dy ∈ [300, H-30]`（每次滑动 ≈0.75×屏高，过小=未滚动/滑到顶
   场景由调用方 dy<40 分支处理；≥屏高=无重叠）——是采集动作的物理量，非人工校准；
3. **像素差验证** `_pixdiff_at`：`absdiff(cur[0:H-dy], prev[dy:H]).mean()`，只用于
   **剔除**假匹配（conf 高但像素差极大），不参与主排序；
4. **conf 最高优先**：内容真实变化时所有 dy 像素差都大（失去区分度），此时
   **模板 conf 最高的带**才是真位移（实测：顶部带 conf 0.999 dy=1421 正确，而
   像素差最小的 845 是次优假匹配）——最终 `dy = max(conf)` 的候选；
5. **多带共识加分**：≥2 带指向同一 dy(|Δ|<20) → conf 提升到 ≥0.85；
6. conf = `1/(1+像素差/20)`（像素差 0→1.0，20→0.5）。

结果：17 对中 16 对与人工校准一致，1 对(13→14)内容真实变化 conf 低(0.45)但值合理
——运行时靠 conf 触发重截/兜底，不需人工介入。

### 13.2 统一裁切线分段（新模块 `src/interaction/loop/cutline_segment.py`）

消息级裁切标准（用户定稿，非常单一，只有两类线）：
- **① 头像上边缘** `avatar_top_lines()`：完整头像顶（`h≥85 且非 low_confidence`，
  贴裁切顶的残缺头像 `y≤15 且 h<105` 跳过——screen_04 曾误把 y=0 残缺头当完整）；
- **② 时间戳上下边沿** `timestamp_edges()`：水平中间段(x∈[250,830])连通圆角矩形，
  OCR 时间格式定位（`\d+:\d+`/昨天）+ 非背景像素上下扩展到"全背景行"边界
  （h∈[15,170]）。

`segment_cutlines(img, roster_matcher, title)`：相邻裁切线之间=一段。
段输出：`y_top/y_bottom/content/factor/avatar_score/nick_score/avatar_cand/nickname`。
**整图一次 slice_chat 后按 y 归属到段**（段内 slice_chat 对裁剪小段识别不可靠）。

与 slice_chat 区别：**不依赖气泡完整性** → 缝合 union 接缝处被切开的跨接缝消息
天然正确处理（slice_chat 会把接缝两边误合并成一条 multimedia）。

### 13.3 接缝黑线修复（裁切起点跳过过渡行）

根因：内容区裁切起点 `detect_pinned_bar_end` 返回黑带(344-365)结束行 366，
但 366 本身是**暗过渡行**(mean≈29，黑带残留)——每张 crop 顶部第一行都是暗线，
stitch 拼接时 B1(=prev_crop[0:split]) 的这条暗线成为接缝黑缝隙
（实测 screen_02 接缝 y=1367 mean=29/dark=100%）。

修复（`page_detector.py`）：黑带结束后若下一行更亮(`row_mean[e+1] > row_mean[e]+10`)
→ 返回 `e+1`（367，第一个真内容行）。19/19 屏稳定，旧背景回归通过。

### 13.4 匹配度数值（`roster_matcher.match_dual_factor` 扩展）

原返回 `(matched, name, best_member_dict)`，数值被丢弃。现返回
`(matched, name, info)`，info 含：
- `avatar_score`：`_match_image_score` 复合分（BGR 模板 + Hue 直方图，抗偏色）；
- `avatar_cand`：该分对应候选成员昵称；
- `nick_score`：OCR 昵称 vs 候选主/群/曾用群昵称的匹配分
  （`_nick_similarity`：完全相等/包含→1.0，否则 LCS 归一化 `2*LCS/(len_a+len_b)`）；
- `thresh`：头像阈值（0.70）。

判定：`avatar_score≥0.70 且 nick_score≥0.60` → 双因子。无昵称 OCR 时
`nick_score = 1.0 if avatar_score≥0.85`（头像高分代偿）。
`chat_slicer` 把 avatar_score/nick_score/avatar_cand 挂到 msg 上供入库/展示。

## 十四、新消息截止点 = 书签截断（2026-08-15 定稿）

### 14.1 语义（用户定稿确认）

**书签 = 上次会话看到的最新位置 = 新消息的截止线**。

```
                更旧（历史，已采过，不重复入库）
                ↑
    ┌─────────────────────┐
    │   更旧内容（历史）    │
    │        ↑            │
    │   ──书签 N0──        │  ← 截止线：上次会话的最新屏（内容区裁图）
    │        ↓            │
    │   新消息（本次要采）  │  ← 书签下方 = 本次新增，全部入库
    │        ↓            │
    │   本次首屏 N1（最新） │  ← 本次进入时的最新屏，结束时存为【下次】书签
    └─────────────────────┘
                ↓
                更新（最新消息）
```

**新消息集 = [书签 N0 上边界, 本次首屏 N1 下边界]**。从书签处截断：
- 书签**下方**（更新侧）= 新消息 = 本次要采集并入库的；
- 书签**上方**（更旧侧）= 历史 = 已采过，不重复入库。

### 14.2 采集循环的停止判定

从 N1（最新）向更早逐屏滚动，**当某次两屏 union 完整包含书签 N0 时停止**：
- 每次滑动 dy < 消息区高 → 书签（1 屏高）从「完全在上一屏」到「完全在下一屏」
  必然经历跨两屏时刻 → 那一刻 union 完整包含书签 → `_anchor_in_union` conf≈1.0；
- 命中后书签下方（更新侧）的新消息已在前面轮次入库 → 不遗漏；
- 结束前把本次首屏 N1 存为下次书签（`_save_anchor`）。

### 14.3 每次滑动的两套去重拼接（共用同一 dy，各自独立）

| | 用途 | 拼接产物 | 识别内容 |
|---|---|---|---|
| ① 书签检测 | 判定「新消息采完没」 | 两屏 union（1.75 屏） | `matchTemplate(union, 书签)` 是否完整包含 |
| ② 去重拼接残缺 | 每条消息识别**一次且仅一次** | A/B 缝合段（A2 上 + B1 下） | 统一裁切线分段 → 入库 |

- 两者**共用同一个 dy**（`find_overlap_dy`），但各自独立拼接一次；
- 重叠区（约 0.75 屏）内容在两张屏都有，但**识别结果只入一次库**（靠去重，
  不靠跳过识别）——故识别重复区是正确性需要，不做增量优化；
- 已评估：dy 检测仅占 10% 耗时（156ms/轮），裁切识别 88%（1268ms/轮，主要是
  OCR）——「增量识别只算新增段」收益不确定，**维持现状**（2026-08-15 定稿）。

### 14.4 真实数据验证（replays/20260814_033410，18 屏）

书签 `collect_anchor_9b11b331742fecab.jpg`（1760×1080，03:32 保存）：

  25ai盛子楠 / 名猫 / 昨天 23:32 / 26cs陈犀 / 19号有啥安排吗）；
