# 交互层（Interaction Layer）

> 三端适配器 + 运行循环组。本层只做两件事：**获取信息**和**发送信息**。
> 循环组和规则判断全部服务于这两件事。不组装 prompt、不调用 LLM、不做决策。
>
> 核心模型：**消息日志是唯一事实源**。本层是"日志同步器 + 动作执行器"——
> 决策层不接收消息内容推送，只收"某某会话日志已更新"的通知，
> 自己按版本指针差分出新增消息。

## 一、核心职责

### 1. 统一接口（本层存在的唯一理由）

```python
# 上行：日志更新通知（轻量，不带消息正文）
LogUpdated(
    session: str,
    version: int,            # 本次日志更新的版本号（每次回传 +1）
    mention_hint: bool,      # 本次更新里疑似含 @我（供决策层优先调度）
)

# 下行读取：决策层按需自取（拼 prompt 的原料）
get_context(session, n=200) -> list[Message]   # 会话历史（含 [@我]/媒体标注）
get_new_since(session, version) -> list[Message]  # 自某版本以来的新增（差分）

# 下行动作：决策层的 XML 动作包落地
submit_bundle(session, reply_blocks_xml) -> ActionResult
    # 一个包多个块如何执行——顺序、拆句间隔、引用怎么点、文件怎么发、
    # 与发现工作的屏幕互斥——全是本层内部事务，决策层无感知
    # ActionResult(ok, error, retryable, escalation_hint)
```

决策层看到的 Android 私聊和 macOS 群聊没有任何结构差异。

### 2. 端口实现（ports/，每端一份）

| 端口 | 消息来源 | 操作方式 |
|---|---|---|
| `android/` | 截图 + 本地 OCR + 区域切段识别 | ADB/root shell（随机化点击/滑动/广播输入） |
| `windows/` | 桌面微信 UI 树（UIA），截图兜底 | 原生输入事件 |
| `macos/` | Accessibility 树，截图兜底 | 原生输入事件 |

端口内部允许硬编码布局标定（一机一份）。输出必须归一化——坐标、像素、
控件树不出本层。

**端口内部是多形态策略组，不是单一实现。** 同一端的获取/操控有多种形式，
按可靠性排序、可插拔、可降级：

- Android：截图+OCR（主）/ 系统通知 dumpsys（辅助信号）/ 无障碍（微信 8.0.52+
  已屏蔽节点，仅作死路记录）
- Windows：UIA 控件树（主）/ 截图+OCR（兜底）/ 系统通知（辅助）
- macOS：Accessibility 树（主）/ 截图+OCR（兜底）/ 系统通知（辅助）

每种形态实现同一个端口接口，切换/降级对上层完全透明。

### 3. 消息日志（全系统的记忆底座）

- 每会话独立持久化（SQLite + 文本导出），msg_uid 幂等
- **回传幂等**：同一条消息无论从哪次同步进来，只入库一次
- 每次成功同步产生一个新 `version`（递增）；决策层记录自己的水位指针，
  `get_new_since` 差分出新增——**这就是"哪些消息是新的"的唯一判定方式**，
  不再需要通知正文猜测、不再需要"有人@我"胶囊点击流程
- 版本/水位之外的易失状态（已读标记等）用有界 LRU 保存，定期清理防爆

**铁律：只要进入一个会话，就必须完成一次日志更新回传才能退出。**
无论是轮询进入还是为执行动作队列进入——动作做完不许直接退，
先同步日志再退。回传失败：重试 N 次后允许退出并标 dirty，
下一轮优先重补（不允许把 agent 卡死在单个会话里）。

### 4. 运行循环组（红点驱动，不再全量轮询）

轮询机制重设计：**首页红点/数字角标就是"该不该进会话"的唯一判据**——
有红点的会话才进入读取，没有的一律不进（消灭空转）。

```
主循环（每周期）：
  回首页 → 解析未读标记（数字红圈/免打扰红点/红色@前缀，含沉底补扫）
  → 有标记的会话：逐个进入 → 滚动读取 → 更新日志 → 回传（version+1）
    → 向决策层发 LogUpdated
  → 无标记：本轮结束（不进任何会话）
  → 空闲时：通知栏监听（近实时辅助）+ 乱逛/退避
```

- 动作执行期间屏幕被占，发现工作顺延（屏幕互斥锁，本层内部机制）
- 执行动作进入会话时，退出前同样走日志同步铁律

### 5. 两个队列

| 队列 | 内容 | 消费者 |
|---|---|---|
| **行动队列** | 决策层投来的 XML 动作包（submit_bundle） | 循环组按序执行（拆原子操作的方式另行规定） |
| **通知队列** | 各会话的"有更新"状态（来自红点扫描/通知栏），驱动读取与 LogUpdated | 循环组 + 决策层调度参考 |

### 6. 行为伪装

- 点击落点/滑动轨迹/等待时长/发送延迟全部随机化
- 长文本拟人分段发送、模拟打字节奏
- 目的：行为统计上像人，规避风控

## 二、明确不做

- 不组装 prompt（只发 LogUpdated + 提供历史/差分读取接口）
- 不调用 LLM（多媒体标注的视觉 API 调用视为感知环节，例外）
- 不做 @我 的处理决策（@识别写进日志，处理逻辑在决策层/Proxy）
- 不包含人格文案
